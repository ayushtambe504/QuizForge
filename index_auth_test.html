Stage 2 · Make QuizForge real

Preserve this quiz experience while moving accounts and records to a secure cloud backend.
BUILD PLAN
01 · Website

Keep the quiz UI

Retain exam tracks, PCMB subjects, chapter filters, per-question timers, explanations, result review, history and CSV export.

02 · Accounts

Supabase Auth

Student sign-up and sign-in, password reset, and a separately granted admin role. Users must never be able to promote themselves.

03 · Question bank

Verified sources

Store exam, subject, chapter, topic, difficulty and source details. Keep correct answers separate from public question content.

04 · Reporting

Secure attempt records

Save score, selected answers, per-question time, total duration and topic performance. Students see only their own records; admins can see cohort reports.

Recommended stack: Supabase Auth + PostgreSQL + Row Level Security, a server-side Supabase Edge Function for grading, and Vercel or Netlify for hosting. The current prototype still stores demo attempts locally and does not transmit student data.

Build in this order

  1. Create a new Supabase project and run the supplied schema after reviewing it.
  2. Wire up authentication and test with two separate student accounts.
  3. Load published questions from the database; keep answer keys server-side.
  4. Create a submit-quiz function that validates answers, grades on the server and saves each attempt.
  5. Build an admin-only reporting screen and test every access rule before launch.
  6. Deploy the frontend and add a privacy notice, account deletion route and source verification workflow.
PYQ source rule: use official papers and content you are permitted to republish, plus licensed or original questions. A question being visible on a website does not automatically make it free to copy. Every PYQ should carry source metadata and be checked against the official answer key.
